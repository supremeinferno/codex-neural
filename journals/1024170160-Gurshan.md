## Technical-mode research flow

- Added the agreed optional technical-mode flow to the web-research wing, not the PDF workflow. When enabled, a separate LLM step rewrites/interprets the research question, and the user can edit that draft before submitting it to the existing research pipeline.
- Kept the workflow intentionally simple: no clarification follow-up; the existing history remains unchanged and records the final prompt actually submitted for answer generation. The original prompt is used when technical mode is off.
- Recorded the architecture and implementation checklist in `backend/technical.md`; implemented the rewrite logic and authenticated endpoint, and added the frontend toggle and draft-editing/review UI. Updated the relevant backend, frontend, and API documentation.

## Research report headings

- Changed research report generation to request `TITLE:` and `REPORT:` sections. The backend parses and limits the title, with a shortened prompt-derived fallback for malformed model output.
- Updated the frontend to show the concise title as the report heading and the full prompt beneath it. The title is included in the existing assistant-history Markdown content so reopened reports retain it without a history schema change.

## Long read-only text presentation

- Added collapsible disclosures with previews for long research prompts in progress and report views. Kept the editable technical-mode draft and generated report expanded.

## Formula rendering and normalization

- Added Markdown math rendering to research reports and PDF answers using `remark-math` and KaTeX, and updated the research and PDF-answer prompts to request conventional LaTeX delimiters.
- Added KaTeX styling and display-math overflow handling, and split math rendering into a separate Vite chunk. Added package overrides to use patched KaTeX 0.18.10; the production dependency audit was clean. The full audit still reported two high-severity development-tool advisories associated with Vite 7.3.6.
- Added `frontend/src/mathMarkdown.js` as a shared normalizer for both report and PDF-answer Markdown. It converts `\(...\)` and `\[...\]`, recognizes standalone equation-like paragraphs (including bracket-wrapped formulas), and normalizes selected parenthetical math expressions. It avoids rewriting inline/fenced code and ordinary currency text.
- Tightened standalone-equation detection after a test showed that prose containing an equation could otherwise be wrapped as a display equation.
- Updated frontend documentation to describe formula normalization and expected delimiters.

## Performance timing and local log analysis

- Added request timing middleware that logs HTTP method, route template, status, duration, and a generated request ID. The ID is returned in `X-Request-ID` and is included in stage timing events for correlation.
- Added stage timings around research search, scraping, and writing; PDF extraction, chunking, vector-store operations, embedding/indexing, retrieval, and answer/summary generation. PDF retry events record operation, attempt, and backoff delay.
- Kept events free of prompts, request bodies, PDF content, query strings, and provider exception messages.
- Added a standard-library command-line analyzer to summarize a local log capture by route and stage, including counts, errors, p50/p95 durations, and retry counts/delays. It can read a file or standard input and needs no metrics service or extra runtime package.
- Documented instrumentation and analyzer usage in `docs/performance-measurement.md` and linked it from the README.
