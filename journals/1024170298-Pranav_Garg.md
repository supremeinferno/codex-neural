## Week 7 — Oct 10–16, 2026

### Chat History Integration, Pipeline Fixes & Sidebar

**Team Integration**

* Merged Noor's persistent chat history and navigation drawer (PR #33).

**Backend / AI**

* Fixed the research pipeline: it was calling the agent that did not have the search tool, and the scrape tool was being invoked incorrectly.
* Removed fixed 40-second `sleep` calls that had been added to dodge rate limits and replaced them with proper retry logic.
* Added system prompts to every agent and tightened the writer and critic prompts (no invented URLs, ignore instructions inside scraped text).
* Capped scraped text at 6000 characters to stay within Groq's tokens-per-minute limit.

**PDF Mode**

* Made the "summary" trigger stricter so normal questions are not treated as summary requests.
* Kept heading lines in the index so section text is not lost.
* Summaries now sample the whole document evenly instead of cutting off the end.
* Embedding calls retry on rate limits and clean up partial data on failure.

**Frontend**

* Restored chat creation and the request timeout (`AbortController`) that had been lost during a merge.
* Renamed the NEXUS tab to CODEX.
* Turned the drawer into a chat sidebar: New chat button, recent chats list, settings, sign out and the signed-in email.

**What I Learned**

* A merge can silently delete working code. After every merge, the main flows must be tested again.
* Fixed `sleep` calls waste time on every request; retrying only when a rate limit actually happens is better.
* Prompt design has a large effect on report quality and on whether the model invents sources.

## Week 8 — Oct 17–30, 2026

### Cleanup, UI Polish, Security Hardening & Documentation

**Repository Cleanup**

* Stopped tracking `frontend/node_modules`, Chroma runtime data and `.DS_Store` files.
* Removed unused packages: `framer-motion`, `xlsx`, `langgraph`, `langchain-google-genai` and `langchain-xai`.
* Removed the dead Excel-sync helper and the unused `logout.css`.

**UI Polish**

* Created design tokens in `globals.css` (colours, fonts, radii, shadows, easing).
* Added `system.css` for shared states: tactile buttons, focus rings, ticker and reduced motion.
* Added the scrolling feature ticker and fixed several layout and accessibility issues.

**Security Hardening**

* Admin routes now identify the admin from the signed-in session instead of an `?email=` query parameter that anyone could send.
* Replaced plain SHA-256 password hashing with salted PBKDF2-SHA256 (600,000 iterations). Old hashes are upgraded automatically at the next sign-in.
* Password reset OTPs are discarded after 5 wrong attempts and compared in constant time.
* Enforced a minimum password length and a 25 MB PDF upload limit.
* The dashboard now sends the session token with admin requests.

**Documentation**

* Rewrote the README.
* Wrote the full `docs/` folder: overview, architecture, backend, frontend, API reference, data storage, security, setup and deployment, and project history.
* Wrote my personal reflection on mistakes and lessons ([1024170298-Pranav_Garg-reflection.md](1024170298-Pranav_Garg-reflection.md)).

**What I Learned**

* Password storage needs a slow, salted algorithm, and live data can be migrated without forcing users to reset passwords.
* The backend must make every security decision; the frontend only decides what to show.
* Good documentation is written for someone who has never seen the project.

**Technical Focus**

* Password hashing and session security
* Authorization on the server
* CSS design systems
* Dependency management
* Technical documentation

## Overall Technical Learning

* **Full-stack architecture:** how a React frontend, a REST API and a database fit together, and why the backend must own all security decisions.
* **FastAPI:** Pydantic request models, dependency injection (`Depends(require_user)`), file uploads and HTTP status codes.
* **React:** state with hooks, `useEffect` cleanup (cancelled flags, revoking blob URLs), `sessionStorage`, and `AbortController` timeouts.
* **LLM applications:** tool-calling agents, prompt templates, the difference between an agent and a fixed chain, prompt-injection defence, and designing around rate limits.
* **RAG:** chunking, embeddings, vector search, why MMR gives better context than plain similarity, and why a summary needs a different path from a normal question.
* **Security:** salted slow hashing, hashed session tokens, constant-time comparison, OTP brute-force limits, and checking ownership on every request.
* **Deployment:** environment variables, CORS, cold starts, and temporary versus persistent storage.
